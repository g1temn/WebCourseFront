# WebCourseFront — план проєкту

Вебплатформа, що збирає в одному місці все про дисципліну **«Web-технології та web-дизайн»**
(ФІТ, НТУ «Дніпровська політехніка»): інформацію про курс, **11 лабораторних робіт** (кожна на окремій
сторінці), редактор коду в браузері для їх виконання (працює з телефона, нічого не треба встановлювати)
та додаткові україномовні матеріали.

- **Зараз робимо:** тільки фронтенд. Дані, які згодом житимуть у базі, повертають сервіси з моками.
  Зміст лабораторних і сторінка «Про курс» — **статичні**, живуть у коді фронтенду.
- **Стек:** React 19 + TypeScript + Vite (вже налаштовано), SCSS Modules, Sandpack для редактора.
- **Адаптивність:** ПК, планшет, телефон (§4).
- **Мова контенту:** лише українська. Без перемикачів теми та мови.
- **Не робимо зараз:** деплой, авторизацію, бекенд, тести, візуальний стиль (обговоримо на етапі 1).

> Ухвалені рішення щодо спірних моментів — у §13.

## 1. Висновки з попередньої спроби (`g1temn/uniWebCourse`)

| Залишаємо | Покращуємо |
|---|---|
| Поділ головної на блоки (Hero, Technologies, FAQ…) | Ці блоки лежали разом з UI-компонентами в одній папці `components/` → тепер кожна сторінка має власну папку **`sections/`** (§10) |
| SCSS Modules, невеликий UI-кіт (`Button`, `InputField`, `TechCard`) | Кожна сторінка сама обгортала себе в `MainLayout` → **layout routes** з `<Outlet />` |
| Тексти hero, підбірка відео | Шляхи до зображень рядками `src/assets/...` ламаються після збірки → імпорт або `public/` |
| | FAQ був lorem ipsum → справжні питання (моки) |
| | Форма відгуку → форма **«Задати питання»** одразу після FAQ |
| | Викладачів поки прибираємо |
| | `.rar`-архіви не відкрити на телефоні → розпаковуємо в `public/labs/<slug>/files/` |

## 2. Що статичне, а що з API

Правило: **змінюється лише разом із самим курсом → статичний файл у репозиторії; змінюється, поки сайт
працює (додають люди чи адмін) → API.**

| Дані | Де | Чому |
|---|---|---|
| Зміст усіх 11 лабораторних, стартові файли для редактора | **Статика**: сторінки лаб (§6) | Однаковий для всіх, змінюється лише з методичкою |
| Список лаб (номер, назва, група, години) | **Статика**: `src/content/labs.ts` | Потрібен сайдбару, таблиці на головній, кнопкам «Попередня/Наступна» |
| Сторінка «Про курс», тексти hero, навігація, футер | **Статика**: `src/content/site/` | Не залежить від бази |
| FAQ | **API (моки)**: `GET /faq` | Поповнюватиметься відповідями на питання |
| Додаткові матеріали (курси, відео, документація) | **API (моки)**: `GET /resources` | Список поповнюватиметься |
| Форма «Задати питання» | **Поки нікуди не надсилає** | Пізніше: `POST /questions` |
| Робочі простори редактора, чекбокси «Ходу роботи» | **Браузер**: `localStorage` | Особисті дані, акаунтів поки немає |

## 3. Навігація — три рівні

1. **Шапка сайту** (усі сторінки): Головна · Про курс · Лабораторні · Пісочниця · Матеріали.
2. **Сайдбар лабораторних** (на сторінках лаб): усі 11 лаб, згруповані HTML / CSS / Figma, поточна підсвічена.
3. **«Зміст сторінки»**: секції поточної сторінки як якірні посилання; активна секція підсвічується під час
   прокрутки. Будується автоматично з секцій, що є на сторінці (§6.2). Також на «Про курс» і «Матеріали».

Плюс кнопки **«← Попередня / Наступна →»** зверху і знизу кожної лаби.

## 6. Сторінки лабораторних

### 6.1 Принцип
**Кожна лаба — окрема сторінка** у власній папці (`pages/labs/Lab1Page/`), складена в JSX з її змісту та
спільних компонентів лаб (§6.3). Тому структура кожної сторінки своя: які секції, в якому порядку і якими
компонентами описано — залежить від змісту конкретної лаби (§6.4).

```tsx
// pages/labs/Lab2Page/Lab2Page.tsx (скорочено)
export default function Lab2Page() {
  return (
    <>
      <LabHeader lab={labs.get("lab-2")} />
      <LabSection id="goal" title="Мета">…</LabSection>
      <LabSection id="images" title="Зображення">
        <p>Вставка картинок здійснюється тегом <code>&lt;img&gt;</code>…</p>
        <RefTable caption="Таблиця 2.1 – Атрибути тега <img>" columns={["Атрибут", "Призначення"]} rows={imgAttributes} />
      </LabSection>
      <LabSection id="lists" title="Списки">
        <CodeListing title="Лістинг 2.1 – Приклад маркірованого списку" lang="html" code={listing21} showResult />
      </LabSection>
      …
      <LabSection id="steps" title="Хід роботи"><StepList labSlug="lab-2" steps={steps} /></LabSection>
      <LabSection id="questions" title="Контрольні питання"><ControlQuestions items={questions} /></LabSection>
      <LabSection id="files" title="Матеріали"><LabFiles labSlug="lab-2" /></LabSection>
    </>
  );
}
```

- Довгі дані (тексти лістингів, рядки таблиць, кроки, питання) винесені поруч у `lab2.data.ts`, щоб JSX
  читався легко. Стартові файли редактора — у `lab2.starter.ts`.
- Якщо сторінка лаби стає надто великою, її секції виносяться в `Lab2Page/sections/`.
- Сторінки лаб підвантажуються **ліниво** через реєстр `content/labs.ts` (пояснення нижче).

> **Що таке ліниве підвантаження.** Без нього Vite збирає весь код сайту в один великий JS-файл, і браузер
> завантажує його повністю ще до показу першої сторінки — разом з усіма 11 лабами, навіть якщо людина відкрила
> лише головну. З `React.lazy` кожна сторінка лаби стає окремим маленьким файлом (chunk), який браузер
> завантажує **лише тоді, коли користувач переходить на цю лабу**. Поки файл вантажиться (частку секунди),
> показується заглушка з `<Suspense fallback={…}>`. Виграш — швидше перше відкриття сайту, особливо з телефона.
>
> ```tsx
> // content/labs.ts — у реєстрі зберігається не сам компонент, а функція, що його завантажить
> { slug: "lab-2", page: lazy(() => import("../pages/labs/Lab2Page/Lab2Page")) }
>
> // router.tsx — сторінка обгорнута в Suspense, який показує заглушку під час завантаження
> <Suspense fallback={<Spinner />}><LabPage /></Suspense>
> ```

### 6.2 Обгортка `LabLayout`
Спільна для всіх лаб: сайдбар, «Зміст сторінки», «Попередня / Наступна». «Зміст сторінки» сам знаходить на
сторінці всі `<LabSection>` (за атрибутом `data-toc`) і будує список — нічого дублювати вручну не треба.

### 6.3 Компоненти для опису лаб (`features/labs/components/`)

| Компонент | Як виглядає | Для чого |
|---|---|---|
| `LabHeader` | Бейдж групи, номер, назва, тривалість, мета, кнопка PDF, «Відкрити редактор» (лаби HTML/CSS) | Початок кожної лаби |
| `LabSection` | Заголовок секції з якорем + вміст; реєструється в «Змісті сторінки» | Кожна секція |
| Типографіка | Звичайні `p`, `ul`, `ol`, `code`, `kbd`, `a` зі стилями контенту лаби | Текст теорії |
| `CodeListing` | Сірий блок: назва → опис → підсвічений код з кнопкою «Копіювати» → (за бажанням) відрендерений результат | Усі лістинги з методичок |
| `RefTable` | Таблиця з необов'язковим полем пошуку | Таблиці тегів/атрибутів/властивостей, спецсимволи, гарячі клавіші, розміри екранів |
| `Callout` | Кольорова плашка: `info`, `warning`, `tip`, `modern` («Сучасний погляд») | Зауваження; застаріле та його сучасна заміна |
| `Figure` | Зображення + підпис, збільшення по натисканню | Рисунки з методичок |
| `Compare` | Дві або більше колонок поруч | UI vs UX, Responsive vs Adaptive, переваги/недоліки фреймів, `display:none` vs `visibility:hidden` |
| `ProcessFlow` | Пронумеровані кроки зі стрілками | Обробка форми (рис. 4.1), етапи створення інтерфейсу |
| `StepList` | Кроки «Ходу роботи» з чекбоксами (прогрес у `localStorage`); крок може містити код, рисунок, нотатку | Практична частина HTML/CSS лаб |
| `StepGallery` | Картка на крок: інструкція + скріншот | Практична частина Figma лаб |
| `ControlQuestions` | Нумерований список питань (без відповідей) | Кінець кожної лаби |
| `LabFiles` | Файли з архіву лаби: прев'ю зображень, перегляд/копіювання текстів, завантаження. **Рендериться лише для лаб з архівом** | Лаби з ✅ у таблиці §5 |
| `RelatedResources` | 2–4 картки україномовних відео/статей до цієї лаби (`GET /resources?lab=`) | Кожна лаба |
| `PrevNext` | ← Попередня / Наступна → | Кожна лаба (через `LabLayout`) |

## 8. Редактор коду (Sandpack)

### 8.1 Вимоги
- HTML, CSS і JS; результат одразу в `iframe`.
- Кілька файлів у робочій папці (створити / видалити).
- Зміни зберігаються після закриття вкладки.
- Працює на телефоні й планшеті.
- Відкривається поруч із завданнями лаби.
- Підтримує те, що потрібно лабам: посилання між HTML-сторінками (№2) і сторінки у `iframe` з `target` (№5).

### 8.2 Як влаштовано
- Пакет `@codesandbox/sandpack-react`, шаблон **`static`** (чисті HTML/CSS/JS).
- Sandpack уже дає: редактор з вкладками файлів, `iframe` з результатом, консоль, автооновлення.
- Наша тонка обгортка `features/editor/`:
  - **`Editor`** — `SandpackProvider` + розкладка (`SandpackCodeEditor`, `SandpackPreview`, `SandpackConsole`).
  - **`FileActions`** — «+ Файл» (ім'я, дозволені `.html .css .js`) і «Видалити» для активного файлу
    через `useSandpack().sandpack.addFile / deleteFile`.
  - **`useWorkspaceStorage`** — завантажує файли на старті, зберігає через ~400 мс після останньої зміни та при закритті вкладки.
  - **«Скинути»** — повертає стартові файли лаби (з підтвердженням).
  - **`LabImages`** — панель зображень лаби (§8.4).
- **Один робочий простір на лабу + одна вільна пісочниця**, одна папка без вкладених, без менеджера проєктів.
  Ключі в `localStorage`: `wc:ws:lab-5`, `wc:ws:sandbox` (пояснення нижче).

> **Що таке `localStorage` і його ключі.** `localStorage` — вбудоване в браузер сховище, де сайт може
> зберігати дані на комп'ютері чи телефоні користувача. Дані не зникають після закриття вкладки чи браузера
> і доступні лише цьому сайту в цьому браузері (на іншому пристрої їх не буде). Сховище працює як словник:
> кожен запис — це пара **ключ → значення**, де обидва — рядки. Ключ — це «назва комірки», за якою запис
> зберігають і потім знаходять. Об'єкти перетворюються в рядок через `JSON.stringify` і назад через `JSON.parse`.
>
> ```ts
> localStorage.setItem("wc:ws:lab-5", JSON.stringify(workspace));    // зберегти файли лаби №5
> const saved = JSON.parse(localStorage.getItem("wc:ws:lab-5") ?? "null"); // прочитати (null, якщо ще нічого немає)
> ```
>
> Наші ключі складаються з частин через двокрапку, щоб не плутатися:
>
> | Ключ | Що зберігає |
> |---|---|
> | `wc:ws:lab-5` | Файли робочого простору лаби №5 (`wc` — WebCourse, `ws` — workspace, далі slug лаби) |
> | `wc:ws:sandbox` | Файли вільної пісочниці |
> | `wc:steps:lab-5` | Позначені чекбокси «Ходу роботи» лаби №5 |
>
> Префікс `wc:` відрізняє наші записи від записів інших бібліотек. Обсяг сховища — близько 5 МБ на сайт,
> для тексту коду цього з запасом.
- Перший крок сесії з редактором — коротка перевірка, що в шаблоні `static` працюють посилання між сторінками,
  `iframe` з `target` і зображення з нашого сайту.

### 8.3 Розкладки
Див. §4: три колонки на ПК, вкладки на планшеті й телефоні, без зміни розмірів панелей.

### 8.4 Зображення в редакторі
Результат Sandpack показується не з нашого сайту, а з сервера CodeSandbox, де є лише текстові файли з редактора:

- ❌ `src="berry.jpg"` або `src="/labs/lab-2/files/berry.jpg"` — браузер шукає файл на сервері CodeSandbox.
- ✅ `src="https://<наш-сайт>/labs/lab-2/files/berry.jpg"` — **повна адреса** файлу з нашого сайту працює.

Щоб студентам не набирати це вручну:
1. Стартові файли лаби вже містять повні адреси потрібних зображень.
2. Панель **«Зображення лабораторної»** показує мініатюри з кнопкою «Копіювати посилання»; адреса будується
   з `window.location.origin`, тож працює і локально, і після деплою.
3. Короткий `info`-callout у лабах з архівом пояснює, чому адреса має бути повною.

## 9. API-шар (моки)

Лише для FAQ і додаткових матеріалів (§2).

```
src/api/
  client.ts            # інтерфейс ApiClient; mock або http залежно від VITE_API_MODE
  mock/
    mockClient.ts      # шлях → обробник, затримка 200–500 мс

  http/httpClient.ts   # на fetch, коли з'явиться бекенд
  services/
    faq.service.ts
    resources.service.ts
```

Компоненти використовують хуки `useFaq()`, `useResources(filter)` на **TanStack Query** (стан завантаження,
помилки, кешування — однаково для моків і справжнього API).

| Метод | Ендпоінт | Повертає |
|---|---|---|
| GET | `/faq` | `FaqItem[]` |
| GET | `/resources?tech=&lab=` | `Resource[]` |
| POST *(пізніше)* | `/questions` | `{ id, createdAt }` |

```ts
type TechGroup = "html" | "css" | "figma";

interface FaqItem {
  id: string; question: string; answer: string; order: number;
  labSlug?: string;             // є → показуємо бейдж «Лабораторна №N»; немає → нічого
}

interface Resource {
  id: string; kind: "course" | "video" | "docs" | "article";
  tech: TechGroup | "js"; title: string; author: string; url: string;
  embedUrl?: string; duration?: string; labSlugs: string[];
}
```

### 9.1 Форма «Задати питання»
- Розташована одразу після FAQ на головній.
- Поля: ім'я*, академічна група, email, лабораторна (випадний список, необов'язковий), питання*.
- Поки **нічого не надсилає**: перевіряє поля, показує повідомлення «Дякуємо! Відповідь з'явиться в розділі FAQ»
  і очищає форму. Тип даних уже готовий для майбутнього `POST /questions`:

```ts
interface QuestionPayload {
  name: string; group?: string; email?: string;
  labSlug?: string;             // необов'язково
  message: string;
}
```
